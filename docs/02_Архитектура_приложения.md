# 02. Архитектура приложения

## 2.1. Общая схема (production)

```
┌──────────────┐     HTTPS :443 / Basic Auth   ┌─────────────────────────────┐
│  Браузер     │ ────────────────────────────► │  Docker: opop_bi_nginx      │
│  (UI)        │ ◄──────────────────────────── │  TLS, HSTS, rate limits     │
└──────────────┘                                └──────────────┬──────────────┘
                                                               │ HTTP web:8000
                                                               │ (сеть backend, internal)
                                                    ┌──────────▼──────────┐
                                                    │  Docker: opop_bi_web│
                                                    │  uvicorn + FastAPI  │
                                                    │  UID 10001          │
                                                    └──────────┬──────────┘
                       ┌───────────────┬───────────────┬───────┴────────┐
                       ▼               ▼               ▼                ▼
                 templates/      static/dist/    runtime/*.sqlite3   data/, uploads/
                 (Jinja2)        (Vite build)   (метаданные)        (Excel-файлы)
```

Порт `8000` **не публикуется** на хост. HTTP `:80` на nginx перенаправляет на HTTPS.

## 2.2. Компоненты backend

| Модуль | Назначение |
|--------|------------|
| `app.py` | Точка входа FastAPI: middleware, маршруты, рендер, upload |
| `settings.py` | Конфигурация из env/`.env`, валидация секретов в production |
| `security.py` | Basic Auth (HTTPS-only), CSRF, CSP/headers, rate limiter |
| `file_registry.py` | Реестр файлов в SQLite, квоты хранилища |
| `data_loader.py` | Парсинг Excel → услуги / классы / статьи затрат |
| `dashboard_builder.py` | KPI, навигация, drill-down по видам затрат |
| `dashboard_cache.py` | In-memory кеш payload по `(file_id, mtime, size)` |
| `file_validation.py` | Структурная валидация XLSX / ZIP |
| `file_validation_worker.py` | Изолированная проверка с таймаутом |
| `logging_config.py` | JSON-логи, ротация, маскирование секретов |

## 2.3. Компоненты frontend

| Артефакт | Источник | Назначение |
|----------|----------|------------|
| `/static/dist/app.css` | Vite + Tailwind | Стили UI |
| `/static/dist/app.js` | `assets/src/app.js` | Меню файлов, upload, CSRF |
| `/static/dist/charts.js` | `assets/src/charts.js` | Chart.js (локально) |
| `/static/dist/excel.js` + `excel.css` | `assets/src/excel.js` | Редактор Univer + ExcelJS |

Шаблоны Jinja2 наследуют `templates/dashboard_shell.html` (CSP nonce, CSRF meta).

## 2.4. Поток обработки запроса (просмотр дашборда)

```
1. nginx (TLS) → Basic Auth (если включён)
2. CSRF token в сессии (для последующих POST)
3. SessionMiddleware → active_file_id (или latest valid)
4. FileRegistry.path_for(record)
5. DashboardPayloadCache.get(file_id, path, loader)
6. Jinja2 TemplateResponse + security headers
```

## 2.5. Поток загрузки Excel

```
POST /api/files/upload (или /api/excel/save-version)
  → CSRF + Origin/Referer
  → rate limit (app + nginx)
  → запись в uploads/.incoming/{uuid}.xlsx
  → MAX_UPLOAD_BYTES / квоты
  → validate_excel_file() (worker + timeout)
  → move в uploads/{uuid}.xlsx
  → INSERT в SQLite (is_latest=1)
  → session.active_file_id = новый id
  → invalidate cache
```

## 2.6. Активный файл и сессии

- Выбор файла хранится в **signed cookie-сессии** (`active_file_id`).
- В production: `Secure` / `https_only`, `SameSite=lax`.
- Выбор действует **только для текущего браузера/сессии**.
- Глобальный «последний» файл (`is_latest`) обновляется при успешной загрузке.
