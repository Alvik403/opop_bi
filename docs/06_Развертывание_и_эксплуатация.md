# 06. Развёртывание и эксплуатация

## 6.1. Требования к серверу

| Компонент | Рекомендация |
|-----------|--------------|
| Кол-во ВМ | 1 |
| ОС | Ubuntu Server 22.04 LTS или 24.04 LTS |
| CPU | 4 vCPU (минимум 2) |
| RAM | 8 ГБ (минимум 4 ГБ) |
| Диск | 80 ГБ SSD (ОС + Docker + data/uploads/logs + резерв) |
| Docker | Docker Engine **29.x** (актуальный stable, напр. 29.7.2) + Compose plugin v2 |
| Сеть | Доступ из VPN/корп. сети; порты хоста **80, 443** (+ 22 для администрирования) |
| Python на хосте | Не обязателен (всё в контейнере) |

## 6.2. Файлы развёртывания

| Файл | Назначение |
|------|------------|
| `Dockerfile` | Multi-stage: сборка frontend + runtime Python (UID 10001) |
| `docker-compose.yml` | Production: nginx `:80/:443` + web (internal `:8000`) |
| `docker-compose.dev.yml` | Разработка: `DEBUG=true` + `ALLOW_INSECURE_DEBUG=true`, bind `127.0.0.1:18000` (**не на сервере**; контейнер `opop_bi_web_dev`) |
| `nginx/` | TLS-сертификаты, шаблон конфига, proxy_params |
| `.env.example` | Шаблон переменных окружения |
| `.env` | Секреты (не в git) |
| `scripts/ops/backup_restore.py` | Резервное копирование / восстановление |
| `scripts/security_check.py` | pytest + pip-audit + npm audit |

## 6.3. Переменные окружения

| Переменная | Описание | Production |
|------------|----------|------------|
| `DEBUG` | Debug-страницы и OpenAPI; auth не выключает | `false` |
| `ALLOW_INSECURE_DEBUG` | Открытый контур без пароля | только dev-compose |
| `SESSION_SECRET` | Ключ cookie-сессий | ≥32 символа, случайный |
| `AUTH_USERNAME` / `AUTH_PASSWORD` | Shared Basic Auth (до SSO) | обязательны в prod; пароль ≥16 |
| `SERVER_NAME` / `ALLOWED_HOSTS` | Имя HTTPS-сервера / Host | обязательны |
| `MONITORING_CIDR` | Сеть для `/health`, `/ready` | по умолчанию `10.0.0.0/8` |
| `TRUSTED_PROXY_IPS` | Список IP для ProxyHeaders | в prod compose пусто |
| `MAX_UPLOAD_BYTES` | Лимит upload | по умолчанию 50 МБ |
| `MAX_UPLOAD_FILES` / `MAX_UPLOAD_STORAGE_BYTES` | Квоты версий | заданы в `.env.example` |
| `XLSX_*` | Лимиты ZIP/XLSX и timeout валидации | заданы в `.env.example` |
| `DATA_DIR` / `UPLOADS_DIR` / `DATABASE_PATH` / `LOGS_DIR` | Пути | в Docker — `/app/...` |

Генерация секрета:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

## 6.4. Быстрый старт (production)

```bash
cd ~/opop_bi
cp .env.example .env
# заполнить SESSION_SECRET, AUTH_*, SERVER_NAME, ALLOWED_HOSTS, MONITORING_CIDR

# TLS-сертификаты
# nginx/certs/fullchain.pem + privkey.pem

mkdir -p data uploads runtime logs
# положить data/data.xlsx
sudo chown -R 10001:10001 data uploads runtime logs

docker compose up --build -d
curl -skI https://127.0.0.1/   # 301/200 через nginx
```

URL: `https://<SERVER_NAME>/` (Basic Auth). Порт `8000` с хоста недоступен.

## 6.5. Порты и контейнеры

| Параметр | Значение |
|----------|----------|
| Хост-порты | `80` → nginx:8080, `443` → nginx:8443 |
| Backend | `web:8000` (только сеть `backend`, `internal: true`) |
| `container_name` | `opop_bi_nginx`, `opop_bi_web` |

**Важно:** на одном сервере с другим BI развести `container_name` и порты 80/443.

## 6.6. Автозапуск

В compose задано `restart: unless-stopped`.

```bash
sudo systemctl enable docker
```

## 6.7. Бэкапы

```bash
python scripts/ops/backup_restore.py backup
# восстановление только после docker compose down:
python scripts/ops/backup_restore.py restore backups/opop-bi-<timestamp>.zip --confirm
docker compose up -d
```

Архивы: `backups/` (не в git). Хранить на зашифрованном носителе.

## 6.8. Обновление

```bash
cd ~/opop_bi
git pull
docker compose up --build -d
python scripts/security_check.py   # рекомендуется
```

## 6.9. Логи

```bash
docker compose logs -f nginx web
tail -f logs/app.log logs/errors.log
```

Логи JSON; секреты маскируются. Docker json-file: 5 × 10 МБ.

## 6.10. Тесты и проверка ИБ

```bash
# unit/security tests
docker compose -f docker-compose.dev.yml build
docker compose -f docker-compose.dev.yml run --rm web \
  sh -c "pip install -r requirements-dev.txt && pytest -q"

# полный security check (pytest + pip-audit + npm)
python scripts/security_check.py
```
